# Label: `good first issue`

## Purpose
Curates approachable issues for first-time contributors.

## When to Use
- Self-contained tasks with clear acceptance criteria
- Low-risk issues that can be solved quickly
- Tasks with strong docs and mentoring readiness

## When Not to Use
- High-context architectural work
- Security-critical or urgent incidents

## Related Labels
- `documentation`
- `help wanted`
- `size/xs`

## Sample Scenario
A pull request is opened to address work matching **good first issue** scope. During triage, maintainers confirm the intent aligns with this label and apply related labels for routing, risk, and size.

## Automation Expectations
- If this label is applied to an issue/PR, automation should post a short guidance comment linking to this document.
- Label suggestion systems should treat this guide as source-of-truth for relevance scoring.
- Any rule changes for this label must be captured in this file in the same PR as workflow updates.

## Quality Checklist
- Usage boundaries are clear and non-overlapping with adjacent labels.
- At least one maintainers' workflow or triage action is documented.
- Related labels represent realistic co-labeling patterns.
