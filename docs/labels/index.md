# Label Catalog

This index is the authoritative catalog for all labels currently managed by this repository.

## Operating Model
- Every label has a dedicated guide describing purpose, boundaries, examples, and automation expectations.
- Label guidance is designed for maintainers, contributors, and bots.
- Changes to label semantics must be made here and then communicated to downstream repos.

## Label Guides

- [`ai-providers`](./ai-providers.md) — Tracks work that integrates, evaluates, or updates AI/LLM provider services.
- [`bug`](./bug.md) — Indicates behavior that does not match expected or documented functionality.
- [`codex`](./codex.md) — Used for issues and PRs focused on agentic coding workflow or Copilot/Codex integration.
- [`critical`](./critical.md) — Marks incidents or changes requiring immediate handling due to severe impact.
- [`dependencies`](./dependencies.md) — Applied to automated or manual dependency update changes.
- [`documentation`](./documentation.md) — For improving docs, onboarding, and developer guidance.
- [`duplicate`](./duplicate.md) — Flags issues or PRs that repeat an already tracked item.
- [`enhancement`](./enhancement.md) — Represents net-new capabilities and requested improvements.
- [`fix`](./fix.md) — Used for pull requests that remediate a known defect.
- [`frontend`](./frontend.md) — For client-facing UI/view-layer implementation and behavior changes.
- [`github-integration`](./github-integration.md) — Tracks integrations with GitHub APIs, webhooks, apps, and repository features.
- [`github_actions`](./github_actions.md) — For CI/CD workflow and GitHub Actions pipeline updates.
- [`good first issue`](./good-first-issue.md) — Curates approachable issues for first-time contributors.
- [`group-b-auth`](./group-b-auth.md) — Represents work scoped to Group B ownership for authentication domain.
- [`help wanted`](./help-wanted.md) — Signals tasks where maintainers are actively inviting outside contribution.
- [`invalid`](./invalid.md) — Marks reports or requests that are not actionable as submitted.
- [`javascript`](./javascript.md) — Classifies changes that modify JavaScript code paths.
- [`Merge to Main`](./merge-to-main.md) — Used to request automatic merge to the default branch when checks pass.
- [`question`](./question.md) — Indicates a request for clarification, validation, or decision support.
- [`security`](./security.md) — Flags vulnerabilities, risk mitigations, and security hardening work.
- [`size/l`](./size-l.md) — Large scope change with broad impact and higher review complexity.
- [`size/m`](./size-m.md) — Medium complexity change with manageable multi-file impact.
- [`size/s`](./size-s.md) — Small scope change with limited impact and straightforward review.
- [`size/xs`](./size-xs.md) — Very small change, ideal for rapid review and merge.
- [`ux`](./ux.md) — For user experience quality improvements spanning flows and interactions.
- [`wontfix`](./wontfix.md) — Marks items intentionally not planned for implementation.
- [`workflow-builder`](./workflow-builder.md) — Covers work on orchestration logic and automation workflow composition.
